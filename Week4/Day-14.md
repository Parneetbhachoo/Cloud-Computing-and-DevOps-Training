
# Day 14 — Amazon EC2 and AWS Cloud Adoption Framework (CAF)

**Training Date:** 20 July 2026

## 2. Topics Covered

### 2.1 Introduction to Amazon EC2

Amazon Elastic Compute Cloud (Amazon EC2) is a cloud computing service provided by Amazon Web Services (AWS). It allows users to create and manage virtual servers, known as instances, on AWS infrastructure.

Instead of purchasing and maintaining physical servers, users can launch EC2 instances and use them to host applications, websites, databases, and other workloads.

#### Key Features of Amazon EC2

- **Virtual Servers:** EC2 instances provide computing environments in the cloud.
- **Scalability:** Computing capacity can be adjusted according to application requirements.
- **Flexible Configurations:** Users can select instance types based on processing power, memory, networking, and workload needs.
- **Operating System Choices:** Instances can use supported operating system images, including Linux distributions and Windows Server.
- **Security Controls:** Security groups help control inbound and outbound network traffic to instances.
- **Flexible Pricing:** AWS offers different pricing options depending on the instance usage model and workload requirements.

### 2.2 Creating an Amazon EC2 Instance

An EC2 instance is a virtual server running on AWS infrastructure. Creating an instance involves selecting the operating system, computing resources, access configuration, and networking settings.

The session included creating an EC2 instance through the AWS Management Console.

The general process for launching an instance is:

1. Sign in to the AWS Management Console.
2. Open the Amazon EC2 service.
3. Select the option to launch an instance.
4. Enter a suitable instance name.
5. Choose an Amazon Machine Image (AMI), which provides the operating system and initial software configuration.
6. Select an instance type according to the required computing resources.
7. Configure a key pair when required for secure instance access.
8. Review network settings and configure the security group.
9. Review the selected configuration and launch the instance.
10. Check the instance state in the EC2 console.

These steps provide an overview of how a virtual server can be provisioned on AWS.

### 2.3 Understanding the AWS Cloud Adoption Framework (AWS CAF)

The AWS Cloud Adoption Framework (AWS CAF) is a framework designed to help organizations plan and manage their cloud adoption journey.

Moving to the cloud involves more than transferring applications from physical servers to cloud infrastructure. Organizations may also need to change their business processes, security practices, operating models, skills, and technology architecture.

AWS CAF helps organizations assess their readiness for cloud adoption, identify areas that need improvement, and develop a structured approach to transformation.

#### Why AWS CAF Is Important

Organizations may face several challenges when adopting cloud computing, such as:

- Understanding their existing IT infrastructure.
- Identifying workloads suitable for cloud migration.
- Preparing employees and teams for new technologies.
- Establishing appropriate security and governance practices.
- Managing operational changes during migration.
- Aligning cloud adoption with business objectives.

AWS CAF provides guidance for addressing these challenges and organizing cloud transformation efforts.

### 2.4 Purpose of AWS CAF in Cloud Migration

**Cloud migration** is the process of moving applications, data, workloads, or IT resources from existing environments to cloud infrastructure.

AWS CAF supports this process by helping organizations understand their current capabilities and prepare for the changes required to adopt cloud services successfully.

Its main purposes include:

- **Assessing Readiness:** Understanding whether an organization has the capabilities needed for cloud adoption.
- **Identifying Gaps:** Finding areas where existing processes, skills, or infrastructure need improvement.
- **Planning Transformation:** Establishing a structured approach to cloud adoption.
- **Improving Governance and Security:** Helping organizations consider risk management, compliance, and security requirements.
- **Supporting Organizational Change:** Preparing teams to work with cloud-based technologies and operating models.
- **Aligning Technology with Business Goals:** Ensuring that cloud adoption supports the organization's broader objectives.

### 2.5 The Six Perspectives of AWS CAF

AWS CAF organizes cloud adoption capabilities into six perspectives. Each perspective addresses a different area of organizational readiness.

#### 1. Business Perspective

The Business perspective focuses on ensuring that cloud adoption supports business objectives and delivers measurable value.

It helps organizations understand how cloud computing can improve business outcomes, reduce costs, and support new opportunities.

#### 2. People Perspective

The People perspective focuses on organizational roles, employee skills, training, and cultural changes.

It helps organizations prepare their workforce for new responsibilities and cloud-based ways of working.

#### 3. Governance Perspective

The Governance perspective focuses on managing cloud adoption through appropriate policies, decision-making processes, risk management, and performance measurement.

It helps organizations establish controls to ensure that cloud initiatives remain aligned with business requirements.

#### 4. Platform Perspective

The Platform perspective focuses on designing, building, and managing cloud infrastructure and technology architecture.

It includes considerations such as cloud services, application architecture, infrastructure design, and migration approaches.

#### 5. Security Perspective

The Security perspective focuses on protecting cloud resources, applications, and data.

It includes areas such as identity and access management, security controls, risk assessment, and compliance requirements.

#### 6. Operations Perspective

The Operations perspective focuses on managing and maintaining cloud environments after deployment.

It includes monitoring, incident management, service management, operational processes, and continuous improvement.

Together, these perspectives help organizations prepare for and manage cloud adoption across business, people, governance, technology, security, and operations.
