
# Day 11 — Git and GitHub: Version Control and Branching

**Training Date:** 14 July 2026

## 1. Overview

Day 11 focused on Git as a Distributed Version Control System (DVCS) and GitHub as a platform for hosting repositories and collaborating on software projects. The session covered repository creation, essential Git commands, branch management, merging, and the fork-and-sync workflow. Hands-on projects involved creating websites, managing code changes, synchronizing repositories, and reviewing commit history.

## 2. Topics Covered

### 2.1 Introduction to Git and GitHub

**Git** is a distributed version control system that tracks changes in files over time. It allows developers to maintain project history, work on different versions of a project, and collaborate efficiently.

**GitHub** is a web-based platform that hosts Git repositories and provides collaboration features such as pull requests, issue tracking, and code reviews.

#### Difference Between Git and GitHub

| Basis of Difference | Git | GitHub |
|---|---|---|
| Definition | Git is a distributed version control system used to track changes in files. | GitHub is an online platform used to host Git repositories and support collaboration. |
| Working | Git can be used locally on a computer without an internet connection for many operations. | GitHub is primarily used online to store repositories and collaborate with others. |
| Purpose | Git manages versions, branches, commits, and project history. | GitHub provides repository hosting, pull requests, code reviews, and collaboration tools. |
| Dependency | Git can work independently without GitHub. | GitHub uses Git for version control of hosted repositories. |

### 2.2 Local and Remote Repositories

A **repository** is a location where project files and their version history are maintained.

- **Local repository:** The copy of a project stored on a computer.
- **Remote repository:** A repository hosted on a platform such as GitHub.

The session covered creating local and remote repositories and connecting them to synchronize project changes.

### 2.3 Essential Git Commands

The following commands were practiced to manage repositories and track project changes.

| Git Command | Purpose |
|---|---|
| `git init` | Initializes a new Git repository in a directory. |
| `git status` | Displays the current state of the working directory and staging area. |
| `git add` | Stages selected changes for the next commit. |
| `git commit` | Records staged changes in the repository history. |
| `git remote` | Manages connections to remote repositories. |
| `git push` | Uploads local commits to a remote repository. |

These commands form the foundation of a typical Git workflow, from initializing a project to saving and sharing changes.

### 2.4 Branching and Merging

A **branch** is an independent line of development within a Git repository. Branches allow developers to work on different features or fixes without immediately changing the main development branch.

The following operations were practiced:

- Creating branches for separate features.
- Switching between branches.
- Making changes independently in different branches.
- Merging branches to combine their changes.

Branching and merging help organize development work and make collaboration easier.

### 2.5 Fork and Sync Workflow

A **fork** is a separate copy of another repository under a user's account. It allows users to experiment with changes or contribute to projects without directly modifying the original repository.

The fork-and-sync workflow was practiced by:

1. Forking a repository.
2. Linking the forked project to a local repository.
3. Making changes to project files.
4. Pushing updates to the remote repository.
5. Synchronizing changes with the original repository.

This workflow is commonly used when contributing to open-source projects or collaborating through separate repository copies.
